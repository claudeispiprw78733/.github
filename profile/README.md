<p>双 ISP 这个词，宣传里出现得比实测里多。它到底指"两条上游线路自动冗余"，还是指"一个 IP 广播到两个运营商"，直接决定这条线值不值那个价。与其听描述，不如自己做一次对照：一组单 ISP 静态住宅，一组宣称双 ISP，同一时段、同一脚本、同一批指标，跑三天，结果自己会说话。</p>
<h2>一、实验设计：先拆开两个变量</h2>
<p>双 ISP 的卖点通常有两层：一是线路冗余，一条断了走另一条；二是出口识别更像真实用户，因为 IP 归属可能落在两个 ASN 之间。这两件事必须分开验证，否则最后分不清是"没冗余"还是"识别不对"。</p>
<table><thead><tr><th>组别</th><th>配置</th><th>固定变量</th><th>观察变量</th></tr></thead><tbody><tr><td>A 组</td><td>单 ISP 静态住宅</td><td>地区、账号、时段</td><td>识别结果、断线次数</td></tr><tr><td>B 组</td><td>宣称双 ISP 住宅</td><td>地区、账号、时段</td><td>识别结果、切换耗时</td></tr><tr><td>对照组</td><td>本机直连</td><td>同一探测脚本</td><td>基线延迟与丢包</td></tr></tbody></table>
<p>账号要分开，别用同一个号在两组之间来回切，否则观测数据会被账号侧的状态污染。每组至少跑 72 小时，覆盖一个完整的工作日和一次周末低峰。</p>
<h2>二、准备：两组出口和一套探测脚本</h2>
<h3>出口侧要记录哪些字段</h3>
<p>开通时就把 ip、asn、org、country、city 五个字段记下来，再查该 IP 的 /24 邻居数量。双 ISP 线路常见的特征是 BGP 前缀挂在两个 ASN 下，用 bgp.he.net 查前缀的 origin AS 能看到多条记录，这条信息比销售页面上的"双线冗余"可靠。</p>
<h3>脚本跑什么</h3>
<p>三段：每 60 秒 curl -x 代理 https://ipinfo.io/json 记录返回的 ip 与 org；每 5 分钟 mtr -c 20 -r 目标域名 记录丢包；每 10 分钟发一次轻量业务请求，记录耗时与状态码。全部落 CSV，字段带时间戳。</p>
<h2>三、观测一：出口会不会被识别成机房</h2>
<p>这是双 ISP 最容易被夸大的地方。有些方案是把住宅段广播到两个上游，出口 IP 的 ASN 仍显示为运营商，识别上没差别；另一些方案是机房段套了个住宅标签，ipinfo 一查 org 就是云厂商。两种情况的体验完全不同。</p>

<h3>怎么判定</h3>
<p>用三个数据源交叉：ipinfo.io 的 org、ipwho.is 的 connection.isp、ip-api.com 的 isp 字段。三处都指向运营商，才算过关；有一处出现机房名字，就要打问号。再看 /24 邻居密度，邻居过密说明这段被反复使用。</p>
<h3>切换前后 ASN 会不会变</h3>
<p>真正的双上游方案，在主线路故障切到备用线路后，出口 IP 可能不变但路径变了，也可能 IP 直接变化。两种都正常，关键是要知道切了。做法是记录每次 IP 变化的时间点，与 mtr 里路径变化的时间点对齐看。</p>
<h2>四、观测二：断线之后切换多快</h2>
<p>冗余的价值全在切换速度上。宣称"自动切换"的方案，实测从 3 秒到 3 分钟都有。测法：主动断开主线路（服务商一般提供切换开关或可申请演练），用 1 秒间隔的探活脚本记录中断时长，重复三次取平均。</p>
<table><thead><tr><th>轮次</th><th>中断时长</th><th>切换后 IP</th><th>首次成功请求耗时</th></tr></thead><tbody><tr><td>第 1 次</td><td>8 秒</td><td>未变化</td><td>11 秒</td></tr><tr><td>第 2 次</td><td>6 秒</td><td>未变化</td><td>9 秒</td></tr><tr><td>第 3 次</td><td>22 秒</td><td>已变化</td><td>26 秒</td></tr></tbody></table>
<p>三次结果差异大，说明切换策略不是纯自动，可能有人工介入或健康检查周期较长。这种表现对长时间挂机的场景可以接受，对需要连续会话的场景就要谨慎。</p>
<h3>还要看"假冗余"</h3>
<p>有些方案两条线路共用同一个上游，主线路断了备用也一起断。验证方法很简单：让服务商分别断开两条上游，看是否都能独立恢复。做不到的，本质上还是单线。</p>
<h2>五、结果怎么读，什么算达标</h2>
<p>把三天的数据摊开，按三个维度打分：识别一致性（三个数据源是否都显示运营商）、冗余真实性（两次断线是否都能独立恢复）、切换可用性（中断是否在 30 秒内）。三项都过，才算名副其实。</p>
<table><thead><tr><th>维度</th><th>达标线</th><th>可接受</th><th>不达标</th></tr></thead><tbody><tr><td>识别一致性</td><td>三源均为运营商</td><td>两源一致</td><td>出现机房 ASN</td></tr><tr><td>冗余真实性</td><td>两次断线独立恢复</td><td>一次独立恢复</td><td>同上游同断</td></tr><tr><td>切换可用性</td><td>30 秒内恢复</td><td>2 分钟内</td><td>超过 5 分钟</td></tr></tbody></table>
<p>如果三项里有两项不达标，多付的溢价就没有对应价值，按普通静态住宅的价格去谈更合理。若只为了"看起来更自然"而买双 ISP，收益往往不如把预算花在邻居更干净的 /24 段上。</p>
<h2>常见问答</h2>
<h3>双 ISP 和双线路是一回事吗？</h3>
<p>答：不是。双 ISP 指上游接入两家不同的运营商，双线路可能只是同一运营商的两条物理链路。前者在单家运营商故障时仍可用，后者不具备这个能力。</p>
<h3>自己怎么验证是不是真双上游？</h3>
<p>答：查 BGP 前缀的 origin AS，看是否挂了两家运营商；再让服务商分别断开每条上游做演练，观察是否都能独立恢复。两项都过才算。</p>
<h3>切换时 IP 变了，账号会不会受影响？</h3>
<p>答：可能。IP 变化本身是事实，影响大小取决于变化范围和频率。记录变化时间点，与账号异常时间点对照，才能判断是否需要调整策略。</p>
<h3>只有一两个账号，值得上双 ISP 吗？</h3>
<p>答：通常不必。单账号的收益主要来自出口稳定和邻居干净，冗余带来的边际价值有限。把预算放在更好的单线上更实际。</p>
<h2>合规提示</h2>
<p>本文的对照测试方法用于评估自有采购线路的实际表现，适用于企业网络选型与验收。测试应仅针对自己的出口与自己的账号，不要对第三方服务发起压力测试。</p>
<p>使用代理服务应遵守所在地法律法规与服务商条款；涉及跨境数据传输的业务需按相关规定履行评估程序。</p>
<p>测试记录中如含 IP、账号等信息，应按内部数据管理要求保存与销毁，不得对外披露或用于其他用途。</p>
